# Auditoria de aplicação, framework e processos

**Escopo:** Prompt 07 de `Otmização VPS.md`. Auditoria estática/read-only em 2026-09-24 (America/Sao_Paulo), checkout atual e documentos anteriores. Não alterei código/configuração/serviços/dados, não iniciei jobs ou requests de carga e não executei testes. Não acessei a VPS, GitHub Actions runs, clientes externos ou segredos.

## Arquitetura e fluxos observados no código

- Frontend é SPA React 18 + TypeScript + Vite; produção gera conteúdo estático servido por Nginx. Chamadas REST usam Axios com cookie/credentials, timeout de 30 s e interceptor de escopo `super-admin`. SSR não faz parte da stack declarada (`frontend/package.json`, Dockerfile e inventory `APP-02`).
- Backend é Java 17/Spring Boot 3.2.5 com Spring MVC, JPA/Hibernate, REST, `@EnableScheduling`, `@EnableAsync`, PostgreSQL e RLS/tenant context (inventory `APP-01`, `DB-*`). API serve integração web, painel, ingestão dos agentes e filas de crawler. Agente desktop Windows é consumidor externo via endpoints autenticados/credenciais próprias, não processo VPS (`APP-03`).
- O estado de runs manuais de crawler é persistido em PostgreSQL com `QUEUED/RUNNING/...`. Um worker Python em loop consulta API, reclama run e grava logs/progresso no bind persistente. Isso é fila funcional, não cache removível. A implementação declarada possui um dispatcher principal e um barcode enricher; presença real e consumidores externos não foram observados.
- Foram encontrados caches locais Java, trabalho assíncrono de auditoria, operações síncronas de imagens/recovery e polling administrativo de crawler. Frequência/concorrência observadas por código não são medição de uso, tempo, CPU ou impacto.

**Achados para priorizar na validação runtime:** o profile `production,jobs` e a API compartilham métodos agendados sem gate de `jobs.enabled`, incluindo a régua de cobrança; o dispatcher manual consulta sua fila a cada 30 segundos embora Compose passe intervalo de seis horas; e os registros de auditoria são gravados por `@Async void` sem fila durável explícita. São riscos/evidências de código, não confirmação de execução ou de falha em produção.
