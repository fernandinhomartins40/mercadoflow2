## Fluxos declarados

### Web/API

`push` em `main` por paths do produto ou `workflow_dispatch` -> GitHub Actions `ubuntu-latest` -> checkout completo e migration guard -> instalar `sshpass`/`rsync` e instalar `.github/vps_known_hosts` -> senha do secret em arquivo temporario protegido -> SSH root com `StrictHostKeyChecking=yes` e fingerprint pinned -> mkdir remoto -> `rsync -az --delete` para `/root/mercadoflow-web` com excludes de env/secrets, `data/catalog`, `data/offers`, backups e artifacts -> `deploy/deploy-web.sh` remoto -> lock, preparar `.env`, validar Compose/volume e backup pre-deploy -> pull base PG/Nginx e build backend/frontend/cron/coletores na VPS (DEP-AUD-18) -> Compose up, Flyway/startup/health/Nginx/grants -> cleanup Docker de containers/imagens/cache desligado no workflow -> `df`/`docker system df`. Retencao separada de dumps (`prune_backups`, 1 por dia/7 dias) continua ativa no script e nao foi executada nesta auditoria. Fluxo declarado, nao executado.

**Gate de persistencia:** Compose usa `data/offers` como bind para outputs/assets e o checkout local nao contem essa pasta. O workflow alterado agora exclui `data/offers` e `data/offers/**` do `rsync --delete`; teste GNU rsync local descartavel retornou 0, preservou offers/catalogo excluidos e manteve o sync/delete do codigo. O conteudo/backup remoto e o comportamento num deploy real continuam NOT VERIFIED; nao houve dry-run remoto nem sync. Nao disparar rollout ate validar secret do Actions, provenance/destino, recovery e acceptance no host.

### Installer do agente Windows

Push nos paths de agent/config, schedule semanal ou dispatch → GitHub Actions `windows-latest`, matriz x64/x86, Node 18 + `npm ci`, package Electron/Inno Setup e geração de installers com sidecars SHA-256/meta → upload de artefatos por 1 dia, sem compressão adicional → job Ubuntu baixa artifacts → SCP temporário `.new` para VPS e `mv` por arquivo → reinicia backend para recarregar bind read-only → consulta API até 150s, verifica status `available` em x64/x86. A própria descrição do workflow registra que o runner Windows não alcança a porta 22 e que a transferência validada ocorre no runner Ubuntu.

Esses são fluxos **declarados no checkout**, não prova de workflow habilitado/execuções atuais, artifacts existentes, tags implantadas ou reachability da VPS.
