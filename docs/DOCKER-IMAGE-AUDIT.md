# Auditoria de Dockerfiles e tamanho de imagens — MercadoFlow

**Data:** 2026-09-24 (America/Sao_Paulo).  
**Prompt:** 03 — Docker e tamanho de imagens, somente auditoria.  
**Ambientes:** evidência estática do checkout local Windows; leitura pontual do Docker Desktop local em contexto `desktop-linux`. A VPS Linux/registry não foi acessada nesta etapa.  
**Segurança/escopo:** nenhum build, pull, push, prune, exclusão de imagem/volume, mudança de serviço/configuração ou carga de produção executada. Nenhum secret ou dado pessoal registrado.

## Resumo

Foram localizados e revisados os **3 Dockerfiles** do inventário: backend Spring Boot/Java, frontend Vite → Nginx e Python collectors. Existem `.dockerignore` próprios nos contextos backend e frontend. A raiz tem outro `.dockerignore`, mas os contexts do Compose apontam para `./backend`, `./frontend` e `./deploy/collectors`; portanto cada contexto tem seu próprio escopo de exclusão.

O código preserva um runtime Java enxuto frente ao builder Maven, um frontend estático sem Node no runtime e uma imagem Python compartilhada entre três funções. As principais oportunidades de estudo são cache de dependências Maven entre alterações de fonte, reprodutibilidade/pinning de base e bibliotecas e user/permissões de runtime. Não apliquei mudanças e não há dados para estimar benefício na VPS.

**Leitura local do daemon:** contexto `desktop-linux`, em 2026-09-24. `docker ps -a --no-trunc` mostrou 18 containers, nenhum em execução; eram projetos locais além do MercadoFlow. `docker image ls` não encontrou tag `mercadoflow*`/`pdv2cloud*` (0). `docker system df` reportou 45 imagens / 45,16 GB (37,48 GB reclaimable), 18 containers / 15,73 MB (15,73 MB reclaimable), 36 volumes / 1,115 GB (862,3 MB reclaimable) e build cache / 35,81 GB (19,55 GB reclaimable; 670 records). Esses valores são do Docker Desktop compartilhado do host, não da VPS nem do projeto. Imagens de build, shared layers, cache, volumes e dados de outros worktrees/projects compõem esse armazenamento; reclaimable do Docker não é recomendação de apagar. Nenhuma imagem alvo do projeto foi medida.

As contagens de `docker system df` não são “tamanho por imagem” e a soma dos tamanhos de tags não mede disco físico exclusivamente atribuível a uma imagem; camadas podem ser partilhadas. A saída detalhada por objeto não foi persistida porque incluiria inventário de outros projetos. Disco/arquitetura/digests na VPS ficam **NOT MEASURED**.

## Conclusões e ações que permanecem apenas candidatas

1. O multi-stage do backend e frontend já evita carregar Maven/Node builder no respectivo runtime. Não assumir que trocar base por Alpine, minificar imagem ou remover package gera redução de disco efetivo; faltam image IDs/tamanhos da VPS e análise de layer share.
2. O cache Maven é o candidato de build com evidência estática mais direta: o POM é copiado antes da source, mas a resolução acontece na mesma instrução após copiar `src`, sem layer/cache explícito de dependências. Medir primeiro, depois testar camada dependency cache preservando plugins Flyway/seed e comparando cold/warm build.
3. A imagem collectors já é compartilhada, instala dependências durante build e usa `--no-cache-dir`; alterações de scripts vêm de bind mount, o que melhora rebuild mas exige consistência source/image na release. `latest` e ranges dependenciais reduzem reprodutibilidade.
4. FFmpeg, `wget` e fontes têm consumidores no produto/probe; não são remoções candidatas neste estado. Um runtime não-root/hardening pode reduzir risco, mas precisa modelar pastas graváveis/ownership e teste com upload/render/health.
5. Docker Desktop local tem armazenamento significativo compartilhado. Nenhum valor foi atribuído ao MercadoFlow ou à VPS e nenhum reclaim foi executado. Recursos de Redis/MinIO/Adminer pertencem a outros containers/stacks locais observados; não são evidência de instalação/uso na VPS nem autorização para apagar.
6. Não se propõe image de migration isolada agora: a aplicação usa o mesmo JAR para Flyway/seeder/serviços, e uma separação precisa resolver ordering, role, seed idempotency e rollback compatível. Não é Prisma, então engine/client/copy links Prisma não se aplicam.
