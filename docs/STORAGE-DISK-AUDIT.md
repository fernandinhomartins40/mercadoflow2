# Auditoria de storage, disco, logs e backups

**Escopo:** Prompt 05 de `Otmização VPS.md`. Auditoria somente leitura de 2026-09-24 (America/Sao_Paulo), checkout local Windows e evidência anterior. Nenhum serviço, código, configuração, arquivo de dado ou volume foi alterado. Não executei prune, expurgo, `rm`, restore, dump ou comando de escrita na VPS.

**Ambiente da evidência:** `docker-compose.vps.yml`, serviços Java/Spring e coletores, código de storage, deploy e docs. Estado operacional VPS (mounts, tamanho real, owner/permissões, bytes físicos, tráfego e retenção existente) permanece indisponível. O host local/checkout não substitui a VPS.

## Resumo

- O perfil VPS declara um volume Docker externo de PostgreSQL e binds para catálogo/imagens/runs e ofertas/renderizações; installer é bind read-only. Vários serviços compartilham o bind de catálogo. Fonte: `docker-compose.vps.yml:12-16,87-90,176-216,256-259` e inventário `VOL-01`, `STO-01..12`.
- Código confirma escrita/leitura de imagens geridas e uploads pelo `CatalogImageStorageService`, armazenamento por filesystem de assets por mercado e renderizações de oferta, além de artifacts e logs de crawler. Esses diretórios são dados necessários ou diagnóstico útil, não candidatos a limpeza sem política e uso confirmados.
- Logging Java envia JSON à console e a `logs/application.json`, com rotação diária por 30 dias e teto de 1 GB no appender de arquivo (`backend/src/main/resources/logback-spring.xml:16-30,40-50`). Isso não limita os logs do driver Docker; nenhum bind de logs é declarado no Compose VPS.
- Deploy declara dump PostgreSQL custom format antes das alterações, valida apenas o TOC com `pg_restore -l`, copia para `${APP_DIR}/backups` e tenta manter um dump por dia durante sete dias (`deploy/deploy-web.sh:285-307,309-349`). Não há prova de backup off-host ou restauração integral testada. A retenção executa remoção automática quando deploy é executado, mas nada foi executado nesta auditoria.
- Os 3 arquivos presentes localmente em `data/` totalizam **73.858.938 bytes (~70,4 MiB)** conforme `Get-ChildItem`/inventário anterior. É o checkout local, não o bind VPS nem ocupação em disco. Pastas locais `data/offers`, `backups` e `logs` não existiam para medição nesta coleta; ausência local não significa ausência no servidor.
- MinIO/S3 não consta na arquitetura declarada. É NOT APPLICABLE à implementação identificada, não prova que não haja serviço/consumidor externo no host. Migração local → objeto não é recomendada sem requisitos de escala, disponibilidade, custos, segurança e compatibilidade de URLs confirmados.
